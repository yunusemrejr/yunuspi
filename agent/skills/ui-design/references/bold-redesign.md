# From scratch, or a big improvement

How to read a request to build a UI from nothing or to improve an existing one in a big way ("big improvement", "completely improve", "tremendously improve", "redesign", "much better", "amazing", "superior"). When the user says the UI/UX, design or aesthetic needs a big improvement, in these or similar words, the default is big, good, bold changes. This file also holds one index of every gallery, example and library the design skills point to. The safe, familiar result is the failure here.

## What the request means

1. **Look at what exists and what does not.** Nothing there: design from scratch. Something there: work on it.
2. **Existing work is judged part by part.** This is not a choice between "keep the design" and "replace the design". Go through the layout, navigation, type, color, components, motion, copy and states one by one. Improve what is good. Redesign what is weak. Keep nothing only because it is already there.
3. **The brand is analysed, then kept.** The name, the logo, what the product is and what it says stay unless the user asks otherwise. Read the brand's own colors, shapes, voice and audience first; every borrowed idea has to be compatible with them.
4. **Big, bold improvements are wanted.** A change the user sees at first glance, in the places where the current result is weakest.
5. **Use the libraries below for real.** Read the guides (`ui-design`, `scrolltide`, `uncommon-web`, `web-motion`, `signature-experience`), open the example pages, templates, components, palettes and fonts they point to, and take the good ideas. Reading an index is not looking at an example: open the live pages in the browser.
6. **Consider what a still page cannot do:** three.js and real 3D, scroll-driven motion, shaders, kinetic type, a tactile widget. Take one strong visual idea per page and keep the rest quiet, in harmony with it.
7. **Iterate a couple of times.** Most of the time, something that looks "nice" at first is not: it is the familiar median. After each pass, look at the screenshot, name what is generic or weak in it, and replace that. Two rounds at least.
8. **AI slop is forbidden.** Before styling, search the web for the current AI-slop design patterns (they change every few months) and avoid them, together with the tells listed in `ui-design`. Named by the owner: a bold curved accent or thick darker edge under a button; blinking or pulsing dot indicators; common pastel colors with the common so-called "aesthetic" fonts.

## When none of this applies

An existing design that is good, that the user is happy with, and that comes with no demand for a big change is good as it is. Keep it, work inside it, and do not go looking for something to redesign. Boldness answers a request for it; it is never a reason to disturb a design that works.

## Working order

1. Inventory the project: brand files, tokens, the best and the worst existing screen (screenshots at 360 px and desktop).
2. Write the verdict per part: keep, improve or redesign, each with a reason.
3. Pick sources from different sections below and open at least three live examples, beyond the first or most familiar one. From each write down what you take: layout skeleton and reading order, type, color logic, spacing rhythm, the one signature move, the states.
4. Choose one direction that would not fit an unrelated product. Say which idea came from which example.
5. Build, screenshot at phone and desktop width, criticise, rebuild. At least twice.
6. Check the screenshots against the tells in `ui-design` and fix every one found.
7. Report the examples and libraries used and what was taken from each.

## Rules

- **Adapt, don't copy.** Borrow mechanics and craft across domains (the scroll logic of a record label for a bakery); never copy templates, text or assets.
- **User and brand first.** Existing brand guidelines and the user's requirements override every source here.
- **Restraint and performance.** One strong visual idea per page. Fast on an ordinary laptop, fully usable at 360 px.
- **Dashboards and daily tools** keep a stable, predictable layout. The boldness goes into craft, color, type, density and states; tactile widgets sparingly, no scroll spectacle.
- **Verify and attribute.** Check the current package version and licence before installing (index recorded October 2026).
