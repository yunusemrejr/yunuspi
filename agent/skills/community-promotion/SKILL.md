# Community promotion

Use for outreach, product launches, forum contributions, guest posts and distribution of useful work. A website build alone does not authorize external posting. Preserve existing explicit publishing authorization; do not repeatedly ask for permission already granted.

Find the audience's actual problem and create something useful even if every promotional link is removed: a worked solution, reproducible example, original observation, comparison with limitations, or practical resource. Disclose affiliation where relevant. Do not invent personal experience, endorsements, identities or community participation.

Read [venue selection](references/venue-selection.md) when finding destinations or evaluating account/API access. Read [execution and learning](references/execution-learning.md) when preparing, publishing or measuring a contribution. Load only the relevant reference.

Check each destination's current posting, promotion, automation and AI-content rules. An available API or logged-in browser does not establish permission. Prefer supported APIs with the user's authorized credentials. If authentication or automation restrictions block a venue, record the blocker and pursue an eligible alternative; do not repeatedly attempt signups or bypass challenges.

Optimize for helpful conversations and qualified visits, not backlink counts or posting volume. Tailor each contribution to its audience; avoid duplicated campaigns, fake grassroots activity, unsolicited bulk messages and ranking manipulation. Link only when useful and permitted; a profile link is not a loophole around promotion rules.

Before an authorized submission, verify the account, destination, exact text, disclosures and links. After an ambiguous response, inspect the existing post before retrying. Return published URLs and observed outcomes separately from drafts and estimates.
