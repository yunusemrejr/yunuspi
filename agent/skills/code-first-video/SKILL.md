# Code-first video direction

Treat the video as software whose output is judged by eye and ear. The failure mode to avoid is a slideshow: text cards with fades. Every beat must show an idea working, a visual system the viewer watches change, not a sentence to read.

For a standalone Blender/FFmpeg film, keep its editable scene and source timeline; a dummy Remotion project is unnecessary. Prove the hero frame and a short motion window before rendering minutes of footage. `blender_render` returns exact review paths and a vision handoff for text-only models. Discover `image_understand action:"models"`, then use an explicit permitted provider/model for pixel review; a PNG read omitted by the main model is not visual evidence. For a fixed-camera ambient film, use an approved detailed plate with `video_ambient` or one verified periodic Blender loop, then extend it with FFmpeg. Check wrap frames and continuous playback. When scene, music and motion investigations can proceed independently, use bounded assistance while the parent builds the proof; keep ownership explicit and reuse source assets. `music_compose` supports standalone local arrangements, while `audio_synth` needs a native video project. Listen to a short musical phrase before committing to the full score.

Start an existing project with `video_project action:"plan"`: it reads the current timeline, asset findings and dependencies and returns exact next calls. Choose `flow:"promo"|"explainer"|"walkthrough"|"longform"|"loop"` for the job (also selectable at init), and `phase:"proof"|"timing"|"assets"|"final"|"delivery"` as work progresses. These are production decisions, not aesthetic templates. Record an optional `beat:{role,claim,visualAction}` per storyboard scene so the visual argument survives edits and narration fitting. Use custom code when native layers cannot express it.

Before expensive full production, run the returned `video_render mode:"review"`. It selects a demanding scene or accepts `scene`, renders full-size critical cue/key/cut-neighbour frames and a decoded playback clip up to 12 seconds in one call. A single Chromium instance serves discovery, stills and playback and closes on success or failure. Read the contact sheet and full-size detail, play the clip and listen; fix the proof before extending that visual language. Inspect `coverage`: long scenes and dense cues can leave omitted evidence, and the selected proof never constitutes whole-film review. Use explicit absolute `from`/`to` for another short window, and stills/preview for all remaining scenes.

Asset craft matters as much as timing. Preserve the complete `creative_direct` brief with `video_project action:"direction"`. Name the focal subject, hierarchy, material/illustration treatment and references before choosing a hero. Build detailed assets with Blender code or licensed models; use `image_generate` with the chosen image model for artwork, backplates, cutouts and textures, then `video_assets import` to retain provenance. Native image/shot/video layers and Blender `image-plane` cards combine these sources. See [hybrid art production](references/hybrid-art-production.md). A ball with eyes is not a complex world asset; more samples cannot repair a weak silhouette. Intentional abstract forms and flat typography can be excellent when the brief calls for them.

Move through the phases in order and do not skip a gate. Read [production pipeline](references/production-pipeline.md) for the artifacts, gates and when to use subagents. Scale ceremony to the job: a 20-second loop needs a short storyboard and one review pass; a three-minute documentary needs research notes, a script, a full storyboard, per-scene reviews and an independent review.

1. **Research → narrative.** Gather facts with sources before writing. Write for the ear: one idea per sentence, concrete nouns, about 3.3–4.3 spoken syllables per second.
2. **Storyboard before code.** For each beat: the claim, the visual metaphor, what moves and why, on-screen text (≤ 8 words), duration. Read [visual language](references/visual-language.md) to turn abstract concepts into visual systems, choose primitives, set typography and use motion to carry meaning.
3. **Master timeline.** `video_project action:"init"` scaffolds a Remotion project whose `video.json` owns scene order, seconds, narration, scene-relative cues, music and sound. Narrative, data and timing live there; components only render. Never hard-code timing that narration depends on.
4. **Implementation.** Start with `video_project action:"compose"`: native layers reserve space for text and media, fit the loaded font, and coordinate gesture/cue timing. Use `hero` layouts for fast staging or explicit normalized `layers` for precise direction. Read [native production](references/native-production.md) for browser framing, tracked device screens, scene graphs and music. Write custom scene components only when the visual argument needs capabilities beyond these tools; keep them parameterised by `video.json`.
5. **Representative-frame review.** `video_render mode:"stills"` returns a labelled contact sheet. Open it with `read` and critique it hard, then fix and re-render. Repeat until every scene passes. Read [QA loop](references/qa-loop.md) for the defect checklist.
6. **Motion review.** `video_render mode:"preview"` per scene or range. Check pacing, easing, transitions and whether motion explains anything. Sample frames around transitions with `video_frames`.
7. **Narration and audio.** `narration_tts` prefers ElevenLabs when configured, voices each scene and writes decoded durations and word spans to the timeline; exact voice/model and local Piper remain selectable. `audio_generate` directs instrumental music and sound accents; `audio_synth` provides local procedural sound. Read [narration and sound](references/narration-and-sound.md).
8. **Sync review, final render, final QA.** Resolve `cueWords` to key words, then run `media_sync` to check text coverage, narration ends and frame timing. Use `video_render mode:"final"` (long films automatically use resumable parts) and continue returned `next` parameters while `complete:false`. Run `video_qa` and `media_sync` on the joined file with `dir` set. Fix errors and review motion and sound around joins before delivery.

Tools beyond the core loop, used when the video calls for them:
- `video_ambient` preserves an approved image/Blender plate for fixed-camera environments. Evolving cloud fields, valley mist, depth-weighted rain, wet-surface distortion/ripples and diffuse lightning share an absolute clock. Author same-canvas sky/fog/rain/reflection mattes; inward feathering protects architecture and dry regions. Use `loop:true` for a complete periodic image-space loop, preview cheaply, then judge full playback and the seam with `video_qa`. It returns actual start/interior/end frames and bounded decoded cadence evidence. This is 2.5D atmosphere: articulated objects, reconstructed geometry, fluids and volumetric clouds need Blender or hosted video. Audio needs its own seam review; technical evidence never approves art.
- `video_project action:"init"` also takes `topic`, `look` (omitted or `derive` builds a palette, type pair, backdrop, voice and music from the subject and steers away from the stock looks; `suggest` lists curated ones; `variation` re-rolls and `accent` anchors a brand colour), `format` (landscape, vertical, square), `intent` (publish or personal) and `platforms`; `action:"look"` swaps the look later, `action:"cta"` places like, follow, comment and share moments, `action:"feature" feature:"3d"` adds the optional three.js `Model3D` primitive.
- `video_shot` renders a Blender camera move (a .blend, an imported model, extruded 3D title or native editable object graph) into `public/shots/<name>` as a transparent frame sequence lit in the film's palette, with named anchors so 2D annotations follow 3D features (`ShotScene`, `ShotNote`). `motion_examples` returns worked examples of advanced motion (vanilla HTML/CSS/JS, WebGL, SVG, Blender scripts, HTML+Blender merges, FFmpeg, numpy) to search, copy and adapt: use it before writing any hero motion from memory, and read the motion-approaches skill to choose and combine approaches and to avoid the stock motion look.
- `video_assets` finds and fetches license-tracked photographs, footage and CC0 3D models (Openverse, Wikimedia Commons, Poly Haven) into `public/assets`, records each license in `assets.json` and adds required credits to `video.json`. Use it when a real photograph or model beats a drawn one; never take media from elsewhere without its license.
- `video_browser` records mobile taps, eased pointer moves, click rings, selector highlights, focused typing and scrolling in a fresh browser, returning a take and observed event timestamps. Inspect the site first, use real selectors, verify responses with `wait_text`, then import the take with `video_assets`. Its portable `.take.json` records source dimensions and observed events. Pass returned `compose.take` to a video layer/hero for cursor-follow framing and click accents; trims and speed use the same source clock. Build longer walkthroughs from bounded takes rather than one fragile browser session.
- `video_shot surface` adds optional brushed-metal, ceramic or organic microdetail and scale-aware bevel highlights while copying existing material nodes. Preview under the final lighting; a stronger texture is not automatically a better material.
- `video_render mode:"thumbnail"` renders the 1280x720 cover from `publish.thumbnail`; `mode:"final"` masters the audio to delivery loudness and writes captions, chapters and a description draft. `audio_synth kind:"sound_design"` places sound accents from the timeline.

Render within the machine's memory: iterate at `preview` scale or a small `width`/`height`, render a `scene` or `from`/`to` range instead of the whole film while iterating, and keep procedural music to the length the video needs. The harness stops any render or synthesis that outgrows its memory budget and says so; when that happens lower the resolution or render in ranges rather than retrying the same request.

For a long film, keep scene IDs, assets and style consistent in one project. Synthesize narration scene by scene; completed cloud chunks and scene updates survive interruption. Render with `mode:"segments", segmentSeconds:45, maxSegments:2` and continue returned parameters until assembly finishes. Parts preserve the global frame clock and PCM audio through joins. Review each section and both sides of a join; a completed part is reusable work, not a finished film. The same tools are available to each LLM, but direction still needs judgment and review for the topic.

See the [worked example](assets/example-attention/README.md) for a complete small project and the defects its review rounds caught.

A successful render or a technical `video_qa` pass establishes file mechanics. `video_qa action:"record"` separately stores explicit art-direction, composition, typography, motion, sync and audio verdicts with observations. Local reference pixels, sampled evidence, project assets and video bytes are bound to the report; changes make old reviews stale. Missing vision/playback/listening stays unreviewed. Only viewed frames, watched motion and measured, listened-to audio establish those qualities.

For a compact SVG or Three.js delivery without a Remotion project, `media_pipeline` accepts an animation source, standalone narration and an editable music score; voice/music roles activate ducking and final AAC measurements. `narration_tts action:"speak"` returns WAV and SRT/VTT timing independently. Resolve narration overruns rather than trimming words. SVG data tracks and CSS/SMIL share an absolute export clock.
