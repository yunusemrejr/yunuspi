# Blender production

The harness drives Blender headless and stages the tools for 3D intents; otherwise `tool_search({ names: ["blender_setup", "blender_inspect", "blender_run", "blender_render", "blender_export"] })`. `blender_setup` installs the pinned local build once if nothing is installed. Never call the `blender` binary from bash: the tools run it guarded, niced, memory-watched and with a deadline, and they parse Blender's output for you.

Workflow:

Large `blender_inspect` results default to a compact summary, with complete worker evidence saved as `inspectionReport`. Use `view:"objects"|"materials"|"animation"`, `offset`, `limit` or exact `names` for detail. Pass the returned `inspectionReport` with the same `blend` to page without launching Blender again; changed blend bytes invalidate reuse. `view:"full"` explicitly requests all worker detail. Coverage and any omitted detail remain visible; a summary cannot approve every object or material.

For a long video, first render one hero frame and a 2–4 second preview with the delivery camera. The tool attaches preview pixels when the main model supports images and offers an `image_understand` handoff otherwise. Discover vision routes before selecting an explicit permitted model; keep visual approval pending until actual pixels were inspected. For a repeating shot, verify periodic motion endpoints and playback before extending the loop. Partition independent scene, music and motion investigations when eligible, while the parent builds and verifies the proof.

1. **Inspect before changing.** `blender_inspect` returns units, render/color settings, world shader sockets, selected-scene lights, area sizes, object scene membership, smooth-face counts, modifiers and animation. Material details include stored shader defaults, immediate links, texture color spaces and packing. A linked socket's default is not its evaluated color; inspect pixels under the intended lighting. Packed textures remain valid when the original external file is absent. Preserve the editable blend and required external dependencies.
2. **Build at the appropriate level.** For a film, `video_shot scene:{objects:[...]}` builds native phone/laptop rigs, smooth primitives, revolved profiles, tubes, text and imported models with parent relationships and transform keys. It keeps editable `.blend` sources and tracked screen corners. Image cards preserve raster alpha; shared line/grid/radial arrays support staggered motion and incoming key easing. Ordered cameraPath keys control position, target and lens with sampled focus distance. Run action:"plan" before rendering to validate inputs and pixel/sample/pass work, then judge a short preview. Use guarded bpy or Geometry Nodes for complex rigged instances or deformation. Use detailed licensed assets for complex heroes; inspect silhouette/materials before adding surface noise. The default for an existing blend preserves its camera, world and lighting. For specialized modeling, **build with the data API**. `blender_run` with inline `code` (or a `.py` `script`) creates or edits scenes: `bpy.data.*` for objects, meshes, materials, cameras, lights and keyframes; `bpy.ops` only in a known mode with the right selection. Name tool-owned objects and collections deterministically so reruns replace instead of duplicate; do not remove unrelated user objects. Save with `bpy.ops.wm.save_as_mainfile(filepath=...)` and print `YUNUSPI_RESULT {json}` for structured return values. Choose geometry, materials, camera and motion to serve the shot; use physical units and one coordinate convention.
3. **Preview cheaply, then judge pixels.** `blender_render mode:"preview"` (quarter resolution, few samples) for framing and motion, `mode:"still"` for representative frames, `mode:"animation" from/to` for sequences (PNG frames, `animation.mp4`, labelled contact sheet). Open the frames with `read` and check silhouettes, clipping, shading, intersections, lighting and temporal continuity. More samples never fix bad lights or broken geometry.
4. **Deliver verified artifacts.** `blender_export` writes glb/gltf (web, `video_project feature:"3d"`), obj/ply/stl, usd, fbx, abc or a packed blend copy; `format:"dataset"` renders a multi-view `transforms.json` set with `init.ply` seed points for Gaussian-splat training with `splat_train` (see the gaussian-splatting skill). Deliver the editable scene and required assets with the render, stating engine, version and any unverified assumptions.

To use a scene in a video, `video_shot` renders a camera move around it into the project as a transparent frame sequence at delivery fps with named anchors for pinned annotations; the motion-approaches skill (and `motion_examples`) has product-hero, materials, camera-rig, geometry-node and HTML-as-screen scripts to start from.

For editorial props, `motion_examples` includes `blender/editorial-umbrella`: authored curved cloth gores, seams/ribs, ferrule and a bent handle, soft lighting and a quiet paper ground. It keeps an editable scene, preserves unrelated objects and keys a closing pose at frame N+1 rather than duplicating it among the N delivered frames. Adapt silhouette, palette, crop and motion to the brief; the example alone is not a complete film.

Read [scene and motion](references/scene-motion.md) for procedural modeling, rigging and physics checks. Read [render pipeline](references/render-pipeline.md) for engine choice, budgets, image sequences and verification. Query the installed bpy API (`blender_run` with introspection code) instead of assuming web examples match the local version. Engines available headless: EEVEE (software GL), Cycles on CPU, Workbench; no GPU is assumed, so keep resolution and samples proportional to the deadline and render long jobs frame-range by frame-range.

For animation debugging, `blender_inspect` accepts up to 12 evaluated frames and exposes layered action channels, interpolation, driver/NLA counts and world transforms. Inspect both stored channels and evaluated motion. `blender_render` holds gaps in stepped source frames at the true scene fps/fps_base; an explicit output fps retimes the sampled frames uniformly. Check the assembled render.json receipt and actual playback before audio composition.
