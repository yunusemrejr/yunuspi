# Engineering reliability audit

This tranche extends existing code-quality, project-intelligence, project-test, skill-discovery, research-profile and notification owners. It adds no tool, model identity policy, parallel cache manager or mandatory review gate. Multimedia, memory/lifecycle, task-state and UI changes are coordinated separately and meet at the combined release commit.

| Reproduced deficiency | Resulting behavior and evidence |
| --- | --- |
| Fixture strings, comments and regular expressions manufactured import edges. The two graph owners also disagreed on resolution. | One lexical import/resolution owner serves both graphs. Cold discovery and runtime graph regressions exclude phantom dependencies and agree on observed module targets. Unsupported JSX/syntax and discovery limits stay explicit; incomplete scans cannot label modules orphaned or packages unused. |
| CommonJS/CTS/Svelte sources were absent from persistent discovery, `.mjs`/`.cjs` imports did not reach their typed source, and Python `from . import sibling` reached only the initializer. | Module variants, typed counterparts, script blocks, Python aliases and sibling/package imports are observed. | A declaration package such as `@types/express` hid the missing runtime package. | Dependency drift reports the undeclared runtime import. This remains an advisory source finding, not authority to install anything. |
| Research profiling read whole metadata files before slicing to 64 KiB, followed metadata symlinks, and hid depth gaps. | Regular-file descriptor reads stop at 64 KiB, special files and symlink leaves are excluded, directory entries are bounded, and depth/unreadable traversal gaps mark the result partial. A 2 GiB sparse README returns its useful prefix without reading the whole file. |
| A notification transaction's lock could be taken from a still-live writer after an age threshold. | Reclamation requires a positively dead PID and moves the exact owner token. Live, malformed and ownerless state times out without deleting ownership. Tests exercise an exited OS process, live ownership and replacement-release safety. |
| Cancelled or invalid skill-discovery attempts poisoned the request fingerprint. | Only a current, validated completion is cached. Valid empty answers avoid further inference; cancelled/unavailable/invalid attempts may retry on the next human input, with one attempt per input and unchanged cancellation/opt-out boundaries. |
| Quoted AND arguments were split as commands; dot-prefixed subdirectories were rejected; an outside symlink directory could bind a project receipt. | Shared check segmentation respects quoting, containment uses the existing path primitive, and existing directory targets are canonicalized. Different symlink targets receive different keys. Missing future build directories remain compatible with explicit plans. |

## Validation and scope

The affected subsystem regression passed 297 tests with no failures or skips, covering code-quality/audit, native syntax, graph workers and warm reuse, model competence, adaptive execution, skill discovery, project-test/quality evidence, coordination and task pipelines. The final graph subset passed 15 tests after additional empty-import, value-named-`type`, JSX and large-module boundaries. Packaging, core-independence, hook/workflow and skill checks passed 35 tests with no failures or skips. The extension-loader syntax check passed over 2,364 tracked source files; new files are also checked explicitly before commit.

The existing tool-efficiency, adaptive execution and competence replay contracts pass with required capabilities preserved. Their output and synthetic scheduling figures are regression constraints, not newly measured billing savings or live model-quality claims. The new deterministic discovery fixture observes zero reparses on its unchanged warm scan. Cache tests observe one successful discovery call followed by zero new calls for identical valid empty advice; invalid attempts do not gain this reuse. No universal latency or cost improvement is claimed.

Source graph corrections increment the parser schema so previously cached relationships are re-observed once. Lexical scans do not implement every framework resolver or parser. Advanced aliases, computed imports and code beyond a reported syntax boundary still require source/parser investigation. Exit-zero receipts prove observed execution, not test coverage or correctness. Skills remain optional guidance and no change removes user controls, observers, subagents, model-provider integrations or required verification.

The final publisher checks the combined commit, generated inventories, public scanner, distribution mirrors, full regression/CI and the guarded state-preserving installation. Focused owner receipts are reused; unchanged whole suites are not run in parallel by every chat. Exact GitHub/local parity and private state preservation are independent acceptance checks.
