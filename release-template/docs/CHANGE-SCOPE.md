# Automatic change-scope decisions

Open-ended revision requests such as “redesign this animation because it is distracting” automatically trigger scope deliberation through project intelligence. Exact edits and read-only questions skip it. The trigger is a bounded language heuristic, not a guarantee of recognizing every phrasing. A short referential follow-up can recover its subject from the current branch.

A compound instruction can qualify the same way when it names its subject by reference rather than repeating it (“do this and that”, “handle the rest”). The council then receives the earlier subject explicitly labelled as historical evidence, never as fresh authority, and it stays unavailable when the earlier request was an exact edit or a read-only question.

The harness reads a bounded selection of relevant messages from the active conversation branch and earlier sessions whose recorded working directory resolves to the same checkout. User statements and assistant claims keep separate provenance and source references. Older evidence can establish a reference; newer user corrections can change it. Missing history, skipped messages and selection limits remain explicit gaps. It does not build a second transcript database or import unrelated projects into the prompt.

Two independent read-only perspectives consider preservation and substantive change. A final council member receives both proposals, challenges unsupported assumptions and discusses the scope. Its brief should distinguish what to preserve, what can be reconsidered, the amount of change, remaining disagreements and acceptance observations. When only two executable routes exist there is no third member, so the critique is authored by one of the two peers; the brief then states that reduced independence instead of presenting a self-review as an independent check. When only one perspective returns, the council still challenges that surviving perspective, marks the result partial, and records the unavailable perspective as an explicit gap rather than silently implying agreement. A distracting interaction may need a new behavior or removal rather than cosmetic adjustments. Conversely, a vague complaint is not a reason to replace an established visual identity or unrelated functionality.

Explicit user direction takes precedence. Assistant-created choices are provisional, but absence of a user request does not prove who introduced a feature; silence is not approval. Historical text and council output are advisory evidence, never instructions or permission. Ordinary design ambiguity calls for reversible judgment rather than routine clarification. Publication, destructive actions and other external effects retain the existing authorization and target checks.

The existing native subagent executor owns dispatch, capability restrictions, provider eligibility and accounting. The council has a shared 240-second deadline (synthesis at most 90 seconds), at most three child launches and a $0.03 total ceiling, subject to stricter user and economy restrictions. It does not hold the turn: the first model request waits at most 15 seconds for it, then the agent reads and inspects while the council deliberates, told that it is still running. The first file mutation (`write`, `edit`, `bulk_edit`) waits for the brief; when a complete brief arrives that no model request has carried yet, that one mutation is returned once, not as an error, with the brief itself in the returned text, so the agent re-checks it against advice it can read and resubmits. A partial council (a timed-out or failed member) is advisory only and never gates a mutation. The final council line in the TUI shows the brief's synthesis, or the finished perspectives when the council is partial. When the deadline expires after the independent perspectives finished, the finished perspectives are kept as a partial result with the missing synthesis named as a gap. The request's own user message being persisted during deliberation is not a version change; genuinely new user input cancels the council directly. No permitted capacity means an explicit unavailable or partial result, and the parent proceeds using available evidence. It never fabricates consensus or retries indefinitely. Relevant turns suppress the separate generic proactive helper team to avoid duplicate startup work. When a council peer fails, its categorized executor row remains available for accounting and the council gap retains a bounded underlying failure diagnostic instead of collapsing the failure into an unexplained unknown.

Deliberation starts during preflight and joins the first context build before inference. At that point the SDK supplies the active cancellation signal. New user input, session transitions and cancellation invalidate stale results. Before publishing the brief, the harness rechecks version references and conversation ancestry; changes during deliberation discard the pending proposals. Ordinary appended accounting entries do not count as a branch switch. One temporary scope brief shares the existing project-context message; context rebuilds replace it. Only operational counts/status and a request hash are added as scope receipts. The original sessions and native child accounting retain their existing private storage behavior.

Completion reviewers receive the earlier council discussion and preservation evidence through the existing project-context adapter. The same 5,000-character review envelope includes exact changed-file graph focus, incoming consumers and outgoing dependencies, plus separate conversation, native checkpoint and project Git references. Fresh Git observations are compared with the initial scope baseline. A new commit or branch marks that baseline as changed; it does not establish a quality pass. HEAD alone cannot establish working-file or index contents.

Observed file changes and review categories can carry those references into the existing graph. Native checkpoint hashes remain in their own namespace; they are not resolved or treated as project commits. Graph connections describe observed provenance, not ownership, causation, approved scope or successful deployment. The graph viewer shows the same relationships available to agents; opening it is optional.

The existing automatic daily-summary workflow also preserves attribution: user direction, assistant choices, council proposals and unverified inferences are distinct. It is instructed to retain scoped corrections and supplied source references, and to avoid treating silence or agent agreement as approval. This changes the existing summary instructions without adding a separate summary call or memory store. Generated summaries remain historical evidence and can still require checking against the original session.

`PI_SCOPE_COUNCIL=off` disables this council. Project intelligence and the native automatic-assistance settings remain respected. Trivial formatting, linting or cleanup requests never qualify for a council; deliberate council use stays available regardless. Child sessions never recursively start their own councils. This workflow supports scope judgment; it cannot certify visual quality, source correctness or deployed behavior. The parent still needs the relevant observations and completion checks.
